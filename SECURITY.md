# Security Policy

## Supported Versions

Security fixes land on the latest major tag. Older majors are not patched.

| Version | Supported |
| :------ | :-------- |
| `v1.x`  | ✅        |
| `< v1`  | ❌        |

Consumers should pin to a full commit SHA (see below) and let Dependabot move
them forward.

## Reporting a Vulnerability

**Do not open a public issue for a security problem.**

Report privately through GitHub:

1. Go to the repository's **Security** tab.
2. Choose **Report a vulnerability** to open a private security advisory.

Please include the affected version or commit SHA, a description of the impact,
and reproduction steps. You can expect an acknowledgement within 5 business days
and a fix or mitigation plan within 30 days for confirmed issues.

## Security Model for Consumers

This action reads a `graph.json` you check out yourself, reads the pull request's
changed-file list, and writes a comment on that pull request. Points worth
understanding before you deploy it:

### Pin the action by commit SHA

A mutable tag can be repointed at new code. For a third-party action that reads
your source, pin the immutable SHA:

```yaml
- uses: mchittineni/blast-radius-check@8f4b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b # v1.0.0
```

### Grant the narrowest possible token

`github-token` needs `pull-requests: write`, and nothing more — that is the only
write this action performs. It never pushes code, never touches your repository
contents, and never calls out to any host but the GitHub API.

The default `${{ github.token }}` is the right choice. If you supply your own
token to comment under a different identity, prefer a GitHub App installation
token scoped to `pull-requests: write` on this repository over a classic PAT with
full `repo` scope.

Withholding `pull-requests: write` degrades gracefully rather than failing: the
analysis still runs and lands in the outputs and the job summary, and the action
logs a warning.

### Treat `graph.json` as sensitive metadata

The graph enumerates repository names, file paths, and dependency versions across
your organization. It does not contain file contents. If your repository names or
internal package names are sensitive, store the graph in a private repository —
and remember that this action renders a slice of it into a pull-request comment,
which is public on a public repository.

### Untrusted repository content

Artifact names, versions, and file paths reach this action by way of a
`graph.json` built from arbitrary repository content. They are escaped before
being rendered into the comment, and no value read from the graph is ever passed
to a shell or evaluated. If you extend the renderer, preserve that property.

### Comment ownership

The action finds its own comment by an embedded HTML marker and edits it in
place, and only ever edits or deletes a comment authored by a bot. A comment
written by a human is never modified, even if it contains the marker.

### `pull_request_target` and forks

Do not run this action from a `pull_request_target` workflow that checks out a
fork's code. That combination grants a write-capable token to untrusted code and
is unsafe regardless of this action.

## Supply Chain

- The committed `dist/index.js` is generated by `npm run build` and verified by
  the `check-dist` workflow on every pull request, so the bundle cannot silently
  diverge from its sources.
- Dependencies are updated by Dependabot and reviewed before merge.
- CodeQL runs on every pull request and on a weekly schedule.
